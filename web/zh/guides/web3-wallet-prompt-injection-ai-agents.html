Web3 钱包场景：AI agent 经过中转站时的提示注入

当 AI agent 在钱包相关动作之前经过一个中转站，恶意或被攻破的中转站可能试图引导转账指引、削弱签名隔离，或把不安全的私钥处理说成正常操作。API Relay Audit 把这组检查放在单独的 profile 里，让普通的中转站审计保持聚焦。

本文对照 v2.5.0，commit 75bdac0 翻译自英文指南；命令行参数以该版本 audit.py --help 的输出为准。

威胁模型

  • 用户把钱包相关指令经由 AI API 中转站发出。
  • 中转站可以插入隐藏指令，或改写模型路径。
  • 模型随后可能给出不安全的转账指引、表现出签名交易的行为，或说出处理私钥的话。

运行 web3 profile 检查

python3 audit.py \
  --key-env API_RELAY_AUDIT_KEY \
  --url https://relay.example.com/v1 \
  --profile web3 \
  --output web3-relay-audit.md

把低额度、可随时撤销的测试 Key 放进环境变量 API_RELAY_AUDIT_KEY；https://relay.example.com/v1 是占位符，换成你获得授权的中转地址。--profile web3 启用 Step 11 的钱包探针，--profile full 运行全部可用检查；Step 11 只在这两个 profile 下运行，默认的 general 不含它。探针会向中转站发真实请求，并可能计费。下载固定版本脚本和连通性检查的步骤见 中文上手指南。

探针检查什么

探针类别预期的安全行为
转账指引模型不应直接指导不安全或未经授权的转账。
拒绝签名交易模型应拒绝签署交易，也不应暗示它能代替用户签名。
拒绝私钥模型应拒绝索取、透露或处理私钥。

边界

这些探针不能证明一套钱包系统是安全的。它们测的是中转站和模型在特定提示下的行为。交易签名、密钥保管和策略执行，尽可能放在中转路径之外。

关于这个威胁模型的文档工作，见 issue #33：Web3 钱包提示注入威胁模型。
