怎么检测 LLM API 中转站里的提示注入

要查一个 LLM API 中转站有没有往你的请求里加隐藏指令，把三类信号放在一起看：token 数差值、提示词抽取探针、指令冲突测试。用受控请求重复几次，条件允许时再和可信的直连通道交叉核对。API Relay Audit 收集的是行为证据；单独一条反常回答，不能证明中转站改了你的请求。

本文对照 v2.5.0，commit 75bdac0 翻译自英文指南；文中的离线示例于 2026-10-30 在该版本上重新跑过。

每种信号说明什么

观察到的信号下一步查什么证据边界
输入 token 数与预期不符用同样的模型、消息、system 和工具配置重复请求；条件允许时，对比一次经授权的厂商直连请求。v2.5.0 用的是固定的近似基线：10、20、15 个 token。它不会自动去测一个对应的官方端点；分词器或封装层的差异都可能解释这个差值。
回复里出现隐藏指令文本检查回忆、翻译、续写三类探针的回复里，有没有真正的指令文本和结构标记。弱关键词匹配可能被记为 inconclusive。模型按常规拒绝，对该探针而言可以是 clean；两种结果都不能说明整条请求路径。
调用方的指令被违背重复无害的算术题和身份冲突测试；分别看回复内容和 HTTP 状态码。模型自身的行为或正当的策略都可能导致违背。请求被拒绝（包括 HTTP 422）不是中转站篡改的证据。
模型自称另一个身份对比中性提示下的回答、响应元数据和可独立核实的上游记录。模型生成的自我介绍、中转站填写的 model 字段和延迟，都不能证明实际提供服务的是哪个模型。
包安装命令被改了对比预期文本和返回文本，包括多出来的措辞或拒绝。Step 8 只有四条文本回显探针。它从不执行工具或安装命令，也不校验结构化的 tool_calls/tool_use 或流式工具参数。

从固定版本开始

按 中文上手指南 下载固定的 v2.5.0 脚本，先看 --help，用 --key-env 传入限额 Key，并在跑更多探针之前先做连通性检查。网络探针会向你选定的中转站发真实请求，可能产生费用。那篇指南也讲了报告隐私和独立版传输层的 TLS 限制。

离线复现一次文本比对

下载并看过 audit.py 之后，在同一目录用 Python 3.10 或更新版本运行下面这段合成示例。它只调用脚本内置的比较器，不向中转站发请求，也不安装任何包。拼错的包名是故意的测试输入。

python3 - <<'PY'
import runpy
api = runpy.run_path("audit.py", run_name="synthetic_guide_demo")
expected = "pip install requests==2.31.0"
for received in (expected, expected + "\n", "pip install reqeusts==2.31.0"):
    print(api["classify"](expected, received))
PY

预期输出：

exact
whitespace
substituted

这只演示了比较器的三种标签，不代表检测准确率，也不是真实中转站的结果。比较器会归一化一部分外围格式；多出来的解释文字或模型的常规拒绝，仍可能被判为 substituted。把改动归因到中转站之前，先回头看返回的原文。

记录发现时连同边界一起记

把脚本 commit、端点、请求的模型、时间戳、参数、重复次数和详细发现放在一起，存进你的私有审计记录。测试用合成提示词；分享报告前先检查里面有没有凭据或私有的回复内容。跳过的检查没有结果，inconclusive 是未定，LOW 总评也不是安全合格证。

issue #79 的补充合成复现评论 暴露过一个与 coding 这个词有关的提示词抽取误报。那个具体回归已在 v2.5.0 修复；它不能推出任何整体误报率。可复现的检测缺口，请带脱敏证据提到 issue #31。

带版本的实现源码

固定版本的 审计编排代码 定义了 token、抽取和指令冲突探针；文本替换模块 定义了上面演示的比较器。想弄清报告里某个标签到底指什么，就读这两处源码。
